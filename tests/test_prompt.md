# Ghidraによるバイナリ解析プロンプト
## 依頼
- GhidraMCPを使用して、現在開いているプロジェクトを解析してください。  
- また、その結果得られた情報をレポートにまとめてください。  
- レポート内に画像を貼り付けて文章のみではなく画像を使用してユーザーに分かるよう工夫してください。

## ディレクトリ
- プロジェクトルート: `C:\\ghidra-work\\XXXX`
- 生成レポート: `<SHA256 hash>_<binary name (exclude file extension, ex: main.exe to main)>_report.md`

## 利用必須ツール
| ツール名 | 動作 |
|---|---|
| `capture_decompiler_png` | 現在表示中のDecompilerペインを保存。対象への移動は事前に行う |
| `capture_evidence` | 指定アドレスへ移動して撮影し、ラベル・関数情報・赤枠を追加 |

## 注意点
### 絶対条件
- `プロジェクトルート`配下でのみ作業する。
### 成果物およびレポート
- 成果物は`プロジェクトルート`配下に配置する。
- 出力形式はMarkdown (.md)
- レポートは以下の段落構成で作成する。
    - タイトル
    - 概要
	- 背景から結果までが一目で分かるサマリーを書く
    - はじめに 
	- 解析対象や調査背景などを述べる
    - 調査
        - 方法
        - 結果
    - 考察
    - おわりに
- 証跡としてスクリーンショットを使用するが、コードや関数全体を写すだけだと理解できない可能性が高いため、コードブロックなどを活用して重要な処理のみを抽出したC/C++疑似コードを作成して分かりやすくする。
- スクリーンショットは特定の処理や関数を写すことになるので、必ずコードの何行目で何が行われているのか明記してください。その上で、コードブロックを使用してより抽象化した疑似コードで説明してください。
- 子プロセス/スレッドの作成や複数の要素が相互に依存しているような処理はMermaid記法を使用して適切なMermaidコード（図）を記述してください。
### 画像取得
- Ghidraの撮影には `ghidra-mcp` の以下だけを使用する。
    - `capture_decompiler_png`
    - `capture_evidence`
- `Computer Use`、`cua_repl`、OSやスクリプトによる画面撮影は禁止する。
- 撮影ツールが未公開の場合は、インスタンスへの接続とutilityグループのロードを確認する。
- 接続や撮影に失敗した場合は、代替手段で撮影せず、エラーを報告する。
- 保存画像の確認は、生成されたPNGファイルを直接読み取って行う。PNGを画面表示して再撮影してはならない。
- 完了時には、使用ツール名、`saved`、`path`、`function`、`entry`を報告する。
- 特徴的・特徴的な処理であっても`capture_evidence`を使用して**赤枠で強調してはいけない**。
### その他
調査の中でファイルを作成、配置する場合は`プロジェクトルート`ディレクトリのみを使用する。
